=====================================================================

LA APP QUE QUIERO:
>>> [ESCRIBE AQUI QUE DEBE HACER LA APP. Ej: "4 fragments: suma, resta,
>>> multiplicacion y division, con una clase para las operaciones"] <<<

Hazla en Android Studio respetando AL PIE DE LA LETRA todas las reglas de
abajo. El codigo tiene que verse escrito a mano por un estudiante con un
estilo muy concreto, NO como codigo "profesional" o "limpio". Si algo no esta
en estas reglas, haz lo mas simple y directo posible, nunca lo mas elegante.
La app tiene que compilar y funcionar cuando el usuario mete bien los datos.

---------------------------------------------------------------------
1. PROYECTO, LENGUAJE Y GRADLE
---------------------------------------------------------------------
- Lenguaje: SOLO Java. Nada de Kotlin.
- Plantilla "Empty Views Activity" de Android Studio, sin modificar:
  paquete com.example.<nombreenminusculas>, minSdk 24, targetSdk 37,
  compileSdk release(37), Java 11 (JavaVersion.VERSION_11).
- NO edites build.gradle.kts ni settings.gradle.kts. Deja las dependencias de
  la plantilla (activity, appcompat, constraintlayout, material, junit,
  espresso). NO agregues dependencias: nada de RecyclerView, ViewBinding,
  DataBinding ni librerias externas. Fragment ya viene con appcompat.
- NO toques colors.xml (solo trae black y white) ni themes.xml. El tema se
  queda en Theme.Material3.DayNight.NoActionBar. UNICA excepcion: si la app usa
  menu de opciones (onCreateOptionsMenu), cambia el parent a
  "Theme.Material3.DayNight" (sin NoActionBar) para que salga la barra.
- El manifest se queda como lo genera la plantilla.
- strings.xml: solo app_name. Si creas un Fragment con el asistente, deja lo
  que genera (el comentario "<!-- TODO: Remove or change this placeholder
  text -->" y el string hello_blank_fragment); no lo borres.
- Nombre del proyecto en diminutivo si se puede: Fragmentitos,
  OperaFragmentitos, llamaditas, combitos, Ahorcadito, ListViewsito.

2. NOMBRES (LO MAS IMPORTANTE)
---------------------------------------------------------------------
- Todo en espanol y en DIMINUTIVO (-ito, -ita, -sito, -sita, -itos, -itas):
    objetos:  objetito, fragmentito, adaptadorsito, alistito, aregresito

              @+id/basesita (FrameLayout donde caen los fragments),
              @+id/vistitas (ListView)

- La variable con el texto del boton presionado SIEMPRE se llama "cadenita".
- La clase modelo/logica se llama "clasesita" o "Clasesita". El objeto que se
  crea de ella SIEMPRE se llama "objetito".
- Las clases propias (fragments, wrappers) pueden ir EN MINUSCULA:
  public class sumitas extends Fragment, public class arraycito.
  MainActivity y Adaptador si van con mayuscula.
- Los numeros leidos van en MAYUSCULAS: int NUM1, int NUM2 (y en la clase
  modelo, campos NUM1, NUM2 con setNUM1/getNUM1). Puedes mezclar con num1 en

- Datos de prueba de relleno: {"uno","dos","tres",...,"diez"},
  {"depo1","depo2",...,"depo10"}. Imagenes con nombre de meme
  (gato_muejeje, veggeto, spiderman, patricio_traje_meme...).
- Algun error de dedo o espacio de mas se vale y se deja asi:
  "fragamentito", texto "NUMERO1 " con espacio al final.

5. CLASE MODELO (clasesita / Clasesita)
---------------------------------------------------------------------
- Campos private (o protected), uno por linea.
- Getters y setters GENERADOS POR EL IDE (Alt+Insert), sin tocar, con
  "this.x = x;". El orden puede ser raro (los de numero2 antes que los de
  numero1). En alguna clase solo hay setters, sin getters.
- Un metodo minimo por operacion, sin parametros, sobre los campos:
      public double suma(){
          return NUM1 + NUM2;
      }
      public double multip(){ ... }  / multiplica() / divide() / resta()
  Llave pegada al parentesis: "suma(){". Sin linea en blanco entre los metodos
  de operacion (si entre los getters/setters, como los genera el IDE).
- Variante: metodos void que MODIFICAN un campo:
      public void costol(){
          costito = 1 * duracion;
      }
  (el "1 *" se escribe aunque sobre).
- SIN constructor, SIN toString, SIN validacion, divide() NO revisa cero.
- Tipos: double en la clase y int al leer (int NUM1 = Integer.parseInt(...);
  objetito.setNUM1(NUM1); se pasa int a un setter double sin problema).
- El objeto se crea DENTRO del manejador cada vez:
      Clasesita objetito = new Clasesita();
  nunca como campo (excepto la lista acumuladora, ver abajo).
- Para guardar varios objetos: clase envoltorio "arraycito":
      public class arraycito {
          ArrayList<clasesita> alistito = new ArrayList<>();
          public void agregar(clasesita objetito){
              alistito.add(objetito);
          }
          public ArrayList regresar(){          <- ArrayList CRUDO, sin <>
              return alistito;
          }
      }
  Y al usarla, asignacion redundante:
      ArrayList<clasesita> aregresito = new ArrayList<>();
      aregresito = alistito.regresar();
      cuantos = aregresito.size();               <- cuantos es CAMPO, no local
      for (int i = 0; i < cuantos; i++) {
          Toast.makeText(this, "Tipo: " + aregresito.get(i).getTipo() + ..., Toast.LENGTH_SHORT).show();
      }
  Codigos como int (tipo 1, 2, 3), nunca enum ni constantes.

10. LAYOUTS XML
---------------------------------------------------------------------
- SIEMPRE LinearLayout. Se cambia a mano el ConstraintLayout raiz de la
  plantilla y se puede dejar algun app:layout_constraint* colgando. NUNCA
  ConstraintLayout, RelativeLayout, ScrollView, CardView ni Material
  components.
- Raiz: android:orientation="vertical", id @+id/main, tools:context y
  margen fijo grande: android:layout_margin="20dp" (fragments) o "50dp", o un
  android:layout_marginTop="120dp" en el primer EditText.
- Orden de atributos de cada vista: layout_width, layout_height, LUEGO
  android:id, luego text/textSize/etc. (el id NO va primero). En vistas con
  margen, el margen puede ir antes del width.
- Ancho siempre match_parent, excepto los botones de operacion
  (wrap_content).
- textSize en dp, NUNCA en sp: android:textSize="30dp", "20dp".
- Texto fijo en el XML, NUNCA @string/: "NUMERO1 ", "NUMERO 2", "+",
  "suma", "resta", "multiplica", "divide", "Local", "Pagar". Texto de los
  botones en minuscula.
- La etiqueta va DEBAJO del campo: primero el EditText y despues el TextView
  "NUMERO1 ". Luego un TextView con el simbolo (+ - * /),
  android:textAlignment="center" y textSize 30dp (en uno de los fragments
  se olvida el textSize).
- EditText SIN android:hint y casi siempre sin inputType (si acaso
  android:inputType="number").
- Tamanos y colores fijos: contenedor de fragments
      <FrameLayout
          android:layout_width="match_parent"
          android:layout_height="600dp"
          android:background="#62D528"
          android:id="@+id/basesita"
          />
  y abajo un LinearLayout horizontal con 4 Buttons wrap_content de texto
  "+", "-", "*", "/".
- Renglon de lista basurita.xml: LinearLayout horizontal con ImageView de
  100dp x 100dp y un LinearLayout vertical con dos TextView (textview con
  textSize 20dp y gravity center; textview2 gravity center).
- "/>" muchas veces en su propia linea. Indentacion a veces mal (hijos con
  8 espacios, o un </LinearLayout> interno pegado a la izquierda).
